Tests differ in what they do to the database, so pgmem offers three shapes. The `pgmemtest` package covers the last two.

| Shape | Setup runs | Cost per test | Use it for |
|---|---|---|---|
| Fresh server per test | every test | server start plus migrations | tests that need a different schema |
| Shared prepared database | once | nothing | tests that only read |
| Fork per test | once | a fork, a few milliseconds | tests that write, and parallel tests |

## A fresh server per test

The simplest shape: every test starts its own server and builds the schema. Nothing is shared, so it is also the slowest when migrations are long.

```go
func TestSchemaVariant(t *testing.T) {
	s, err := pgmem.Start(t.Context(), pgmem.Options{Database: "app"})
	if err != nil {
		t.Fatal(err)
	}
	t.Cleanup(func() { s.Close() })

	db, err := sql.Open("pgx", s.DSN())
	if err != nil {
		t.Fatal(err)
	}
	t.Cleanup(func() { db.Close() })
	if _, err := db.Exec(schemaV2); err != nil {
		t.Fatal(err)
	}
	// ...
}
```

## Prepare once in TestMain

`pgmemtest.Run` starts a template server, runs `Prepare` once, snapshots the result, runs the tests and cleans up.

```go
package store_test

import (
	"context"
	"database/sql"
	"os"
	"testing"

	"github.com/shibukawa/pgmem"
	"github.com/shibukawa/pgmem/pgmemtest"
)

var fx *pgmemtest.Fixture

func TestMain(m *testing.M) {
	os.Exit(pgmemtest.Run(m, pgmemtest.Options{
		Options: pgmem.Options{Database: "app"},
		Prepare: func(ctx context.Context, db *sql.DB, dsn string) error {
			if err := migrateUp(dsn); err != nil { // golang-migrate, goose, Atlas ...
				return err
			}
			return seed(ctx, db) // dbtestify, SQL, COPY ...
		},
	}, func(f *pgmemtest.Fixture) { fx = f }))
}
```

`Prepare` receives a `*sql.DB` already connected in-process and the DSN for tools that want a URL. The migration and seed code from [the basics](../basics/) goes here unchanged.

## Share the prepared database with read-only tests

Tests that only read can use one database. Take one fork for the whole package in `TestMain`, or use the template directly:

```go
var readOnly *sql.DB

func TestMain(m *testing.M) {
	os.Exit(pgmemtest.Run(m, opts, func(f *pgmemtest.Fixture) {
		fx = f
		shared, err := f.Snapshot().Fork(context.Background())
		if err != nil {
			panic(err)
		}
		readOnly, _ = sql.Open("pgx", shared.DSN())
	}))
}

func TestReportTotals(t *testing.T) {
	t.Parallel()
	var total int
	if err := readOnly.QueryRow("SELECT sum(amount) FROM orders").Scan(&total); err != nil {
		t.Fatal(err)
	}
}
```

<Aside type="caution">
A shared database is only safe while no test writes to it. One test's `INSERT` becomes another test's surprise, and the failure depends on test order.
</Aside>

## A fork per test for tests that write

Each helper takes `t`, forks the snapshot, and closes the fork when the test ends. Forks are independent, so `t.Parallel()` is safe.

<Tabs syncKey="go-driver">
<TabItem label="database/sql">

```go
func TestCreateOrder(t *testing.T) {
	t.Parallel()
	db := fx.DB(t) // in-process connection to a fresh copy

	if _, err := db.Exec(`INSERT INTO orders (user_id, amount) VALUES (1, 500)`); err != nil {
		t.Fatal(err)
	}
}
```

</TabItem>

```go
func TestCreateOrder(t *testing.T) {
	t.Parallel()
	conn := fx.PgxConn(t)
	_, err := conn.Exec(t.Context(), `INSERT INTO orders (user_id, amount) VALUES (1, 500)`)
	if err != nil {
		t.Fatal(err)
	}
}
```

`fx.Fork(t)` returns the `*pgmem.Server` itself when you need both `DSN()` and `Dial`.

### Assert what the test wrote

dbtestify compares the database with an expected data set and reports a table diff on mismatch:

```go
import (
	"github.com/shibukawa/dbtestify"
	"github.com/shibukawa/dbtestify/assertdb"
)

func TestCancelOrder(t *testing.T) {
	t.Parallel()
	db := fx.DB(t)

	if err := CancelOrder(t.Context(), db, 1); err != nil {
		t.Fatal(err)
	}
	assertdb.AssertDBWithDB(t, db, dbtestify.PostgresDialect, testdata, "testdata/after_cancel.yaml", nil)
}
```

## Parallelism and memory

Every live fork holds its own copy of the data directory and buffer cache. `MaxForks` caps how many exist at once and defaults to `GOMAXPROCS`, which matches `go test`'s default parallelism. A test that asks for a fork while the pool is full waits until another test ends; cancelling the test context aborts the wait.

```go
pgmemtest.Options{MaxForks: 4, /* ... */}
```

<Aside>
Connection pools on one fork work, but queries on the same fork serialize at transaction boundaries. Run independent tests in parallel on separate forks instead. See [limits](../../../limits/).
</Aside>
