pgmem for the JVM is three artifacts: `io.github.shibukawa.pgmem:pgmem` (the client), `io.github.shibukawa.pgmem:pgmem-junit5` (the JUnit 5 extension) and `io.github.shibukawa.pgmem:pgmem-native` (the binary, one classifier per platform). The client has no third-party runtime dependencies; bring your JDBC driver.

## Dependencies

The classifiers are `linux-x86_64`, `linux-arm64`, `darwin-x86_64`, `darwin-arm64`, `windows-x86_64` and `windows-arm64`. When a build runs on several platforms, pick one per platform with Maven profiles or a Gradle OS detection plugin rather than depending on all six. The binary is extracted once into `~/.cache/pgmem/<version>/`. Java 17 or newer.

## The basic flow

<Steps>

1. **Start the process.** `Pgmem` is `AutoCloseable`; closing it stops every server.

   <Tabs syncKey="jvm-lang">
   <TabItem label="Java">

   ```java
   try (Pgmem pg = Pgmem.builder().database("app").start()) {
       Server template = pg.template();
       System.out.println(template.jdbcUrl()); // jdbc:postgresql://127.0.0.1:54321/app?user=postgres&sslmode=disable
   }
   ```

   </TabItem>
   <TabItem label="Kotlin">

   ```kotlin
   Pgmem.builder().database("app").start().use { pg ->
       val template = pg.template()
       println(template.jdbcUrl())
   }
   ```

   </TabItem>
   </Tabs>

   The builder also takes `user(...)`, `param("shared_buffers", "128MB")`, `log(true)` and `binary(path)`.

2. **Register the schema** with a migration tool. See [migration tools](#migration-tools).

3. **Load seed data.** See [seed data](#seed-data).

4. **Use it through JDBC.** `jdbcUrl()` carries the user and `sslmode`, and `dataSource()` returns a `javax.sql.DataSource`.

   <Tabs syncKey="jvm-lang">
   <TabItem label="Java">

   ```java
   try (Connection conn = DriverManager.getConnection(template.jdbcUrl());
        PreparedStatement ps = conn.prepareStatement("SELECT name FROM users WHERE id = ?")) {
       ps.setLong(1, 1);
       try (ResultSet rs = ps.executeQuery()) {
           rs.next();
           String name = rs.getString(1);
       }
   }
   ```

   </TabItem>
   <TabItem label="Kotlin">

   ```kotlin
   DriverManager.getConnection(template.jdbcUrl()).use { conn ->
       conn.prepareStatement("SELECT name FROM users WHERE id = ?").use { ps ->
           ps.setLong(1, 1)
           ps.executeQuery().use { rs -> rs.next(); println(rs.getString(1)) }
       }
   }
   ```

   </TabItem>
   </Tabs>

   A HikariCP pool on the URL works too; its connections serialize at transaction boundaries.

</Steps>

## Migration tools

<Tabs syncKey="jvm-migrate">
<TabItem label="Plain SQL">

```java
String schema = Files.readString(Path.of("src/test/resources/schema.sql"));
try (Connection conn = DriverManager.getConnection(template.jdbcUrl());
     Statement st = conn.createStatement()) {
    st.execute(schema);
}
```

</TabItem>
<TabItem label="Flyway">

```java
Flyway.configure()
      .dataSource(template.jdbcUrl(), template.user(), null)
      .locations("classpath:db/migration")
      .load()
      .migrate();
```

Flyway 10 and later also need `org.flywaydb:flyway-database-postgresql` on the test classpath.

</TabItem>
<TabItem label="Liquibase">

```java
try (Connection conn = DriverManager.getConnection(template.jdbcUrl())) {
    Database db = DatabaseFactory.getInstance()
            .findCorrectDatabaseImplementation(new JdbcConnection(conn));
    new CommandScope("update")
            .addArgumentValue("database", db)
            .addArgumentValue("changelogFile", "db/changelog/db.changelog-master.yaml")
            .execute();
}
```

</TabItem>
</Tabs>

## Snapshot and fork by hand

```java
try (Pgmem pg = Pgmem.builder().database("app").start()) {
    migrate(pg.template().jdbcUrl());
    Snapshot snap = pg.template().snapshot();          // waits for open transactions, 30 s
    try (Fork fork = snap.fork()) {                     // a private copy
        DataSource ds = fork.dataSource();
        // ...
    }
}
```

Commit or close every connection to the template before `snapshot()`. The JUnit 5 extension on the [next page](../testing/) wires this into the test lifecycle.
