pgmem for the JVM has a core client (`io.github.shibukawa.pgmem:pgmem`), testing modules (`pgmem-junit5`, `pgmem-spring`, and `pgmem-micronaut`), and a platform-specific binary (`pgmem-native`). The client has no third-party runtime dependencies; bring your JDBC driver.

## Dependencies

```kotlin title="build.gradle.kts"
val pgmemOs = System.getProperty("os.name").lowercase()

    pgmemOs.contains("mac") || pgmemOs.contains("darwin") -> "darwin"

val pgmemCpu = when (pgmemArch) {
    "amd64", "x86_64" -> "x86_64"

val pgmemNative = "$pgmemPlatform-$pgmemCpu"

dependencies {
    testImplementation("io.github.shibukawa.pgmem:pgmem-junit5:1.18.0")          // pulls in io.github.shibukawa.pgmem:pgmem

    testImplementation("org.junit.jupiter:junit-jupiter")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher")
}

    useJUnitPlatform()
}
```

The classifiers are `linux-x86_64`, `linux-arm64`, `darwin-arm64`, `windows-x86_64` and `windows-arm64`. When a build runs on several platforms, pick one per platform with Maven profiles or a Gradle OS detection plugin rather than depending on all five. The binary is extracted once into `~/.cache/pgmem/<version>/`. Java 17 or newer.



The Gradle examples select the classifier from the build host. With Maven, pass it explicitly, for example `mvn -Dpgmem.native.classifier=linux-x86_64 test`, or add the profiles below to select it automatically on multiple hosts. Intel Macs have no native artifact; omit the native dependency and use a local build through `PGMEM_BINARY`.

If the existing Maven build does not already run JUnit 5 tests, add this build configuration as well.

```xml
<build>
  <plugins>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-compiler-plugin</artifactId>
      <version>3.14.0</version>
      <configuration><release>17</release></configuration>
    </plugin>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-surefire-plugin</artifactId>
      <version>3.5.4</version>
    </plugin>
  </plugins>
</build>
```

## The basic flow

<Steps>

1. **Start the process.** `Pgmem` is `AutoCloseable`; closing it stops every server.

   <Tabs syncKey="jvm-lang">
   <TabItem label="Java">

   ```java
   try (Pgmem pg = Pgmem.builder().database("app").start()) {
       Server template = pg.template();
       System.out.println(template.jdbcUrl()); // jdbc:postgresql://127.0.0.1:54321/app?user=postgres&sslmode=disable
   }
   ```

   </TabItem>
   <TabItem label="Kotlin">

   ```kotlin
   Pgmem.builder().database("app").start().use { pg ->
       val template = pg.template()
       println(template.jdbcUrl())
   }
   ```

   </TabItem>
   </Tabs>

   The builder also takes `user(...)`, `param("shared_buffers", "128MB")`, `log(true)` and `binary(path)`.

2. **Register the schema** with a migration tool. See [migration tools](#migration-tools).

3. **Load seed data.** See [seed data](#seed-data).

4. **Use it through JDBC.** `jdbcUrl()` carries the user and `sslmode`, and `dataSource()` returns a `javax.sql.DataSource`.

   <Tabs syncKey="jvm-lang">
   <TabItem label="Java">

   ```java
   try (Connection conn = DriverManager.getConnection(template.jdbcUrl());
        PreparedStatement ps = conn.prepareStatement("SELECT name FROM users WHERE id = ?")) {
       ps.setLong(1, 1);
       try (ResultSet rs = ps.executeQuery()) {
           rs.next();
           String name = rs.getString(1);
       }
   }
   ```

   </TabItem>
   <TabItem label="Kotlin">

   ```kotlin
   DriverManager.getConnection(template.jdbcUrl()).use { conn ->
       conn.prepareStatement("SELECT name FROM users WHERE id = ?").use { ps ->
           ps.setLong(1, 1)
           ps.executeQuery().use { rs -> rs.next(); println(rs.getString(1)) }
       }
   }
   ```

   </TabItem>
   </Tabs>

   A HikariCP pool on the URL works too; every connection gets its own backend process.

</Steps>

<TabItem label="Flyway">

```java
Flyway.configure()
      .dataSource(template.jdbcUrl(), template.user(), null)
      .locations("classpath:db/migration")
      .load()
      .migrate();
```

Flyway 10 and later also need `org.flywaydb:flyway-database-postgresql` on the test classpath.

</TabItem>
<TabItem label="Liquibase">

```java

    Database db = DatabaseFactory.getInstance()
            .findCorrectDatabaseImplementation(new JdbcConnection(conn));
    new CommandScope("update")
            .addArgumentValue("database", db)
            .addArgumentValue("changelogFile", "db/changelog/db.changelog-master.yaml")
            .execute();
}
```

## Snapshot and fork by hand

```java
try (Pgmem pg = Pgmem.builder().database("app").start()) {
    migrate(pg.template().jdbcUrl());
    Snapshot snap = pg.template().snapshot();          // waits for open transactions, 30 s
    try (Fork fork = snap.fork()) {                     // a private copy
        DataSource ds = fork.dataSource();
        // ...
    }
}
```

Commit or close every connection to the template before `snapshot()`. The JUnit 5 extension on the [next page](../testing/) wires this into the test lifecycle.
