---
title: Testing with Vitest, Jest, node:test and Bun
description: Three ways to use pgmem in Node.js tests - a fresh server per test file, one prepared database shared by read-only tests, and a reset or fork per test for tests that write.
---

import { Tabs, TabItem, Aside } from '@astrojs/starlight/components';

Node.js test runners load each test file in a fresh worker or module context, and an ORM client reads `DATABASE_URL` once, when it is created. pgmem fits that shape: one pgmem process for the run, a fork per test file exposed as `DATABASE_URL` before the file is imported, and a reset in place between tests. Setting `DATABASE_URL` per test case would not help, because the client already holds the URL.

| Shape | Setup runs | Cost per test | Use it for |
|---|---|---|---|
| Fresh server per test file | every file | process start plus migrations | files that need their own schema |
| Shared prepared database | once per run | nothing | tests that only read |
| Reset or fork per test | once per run | a reset or fork, about 15 ms | tests that write |

## A fresh server per test file

```ts title="schema-variant.test.ts"
import { PgmemServer } from '@pgmem/core';
import { afterAll, beforeAll, test } from 'vitest';

let server: PgmemServer;

beforeAll(async () => {
  server = await PgmemServer.start({
    database: 'app',
    control: false,
    prepare: ({ url }) => applySchemaV2(url),
  });
});

afterAll(() => server.close());

test('reads the new column', async () => {
  // connect to server.url
});
```

## Prepare once for the run

Start the server in the runner's global setup and export `server.env()`. It carries `PGMEM_CONTROL` and `PGMEM_SNAPSHOT`, which is how test processes reach the server and its snapshot.

<Tabs syncKey="node-runner">
<TabItem label="Vitest">

```ts title="test/global-setup.ts"
import { execFileSync } from 'node:child_process';
import { PgmemServer } from '@pgmem/core';

export async function setup() {
  const pg = await PgmemServer.start({
    database: 'app',
    prepare({ url }) {
      execFileSync('npx', ['prisma', 'migrate', 'deploy'], {
        stdio: 'inherit',
        env: { ...process.env, DATABASE_URL: url },
      });
    },
  });
  Object.assign(process.env, pg.env());
  return () => pg.close();
}
```

```ts title="vitest.config.ts"
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    globalSetup: ['./test/global-setup.ts'],
    setupFiles: ['@pgmem/core/register'],
  },
});
```

</TabItem>
<TabItem label="Jest">

```js title="jest.config.js"
module.exports = {
  globalSetup: './test/global-setup.js',
  globalTeardown: './test/global-teardown.js',
  testEnvironment: '@pgmem/core/jest-environment',
};
```

```js title="test/global-setup.js"
const { PgmemServer } = require('@pgmem/core');

module.exports = async () => {
  globalThis.pgmem = await PgmemServer.start({ database: 'app', prepare: ({ url }) => migrate(url) });
  Object.assign(process.env, globalThis.pgmem.env());
};
```

```js title="test/global-teardown.js"
module.exports = () => globalThis.pgmem.close();
```

The environment gives each Jest worker one fork and resets it between the test files that worker runs. It needs `jest-environment-node`, which Jest installs.

</TabItem>
<TabItem label="node:test">

```js title="test/global-setup.mjs"
import { PgmemServer } from '@pgmem/core';

let pg;
export async function globalSetup() {
  pg = await PgmemServer.start({ database: 'app', prepare: ({ url }) => migrate(url) });
  Object.assign(process.env, pg.env());
}
export async function globalTeardown() {
  await pg.close();
}
```

```sh
node --test --test-global-setup=./test/global-setup.mjs --import @pgmem/core/register
```

Global setup needs Node.js 24 or newer. Each test file runs in its own process, so `--import` gives every file its fork.

</TabItem>
<TabItem label="Bun">

```js title="test/run.mjs"
import { spawnSync } from 'node:child_process';
import { PgmemServer } from '@pgmem/core';

const pg = await PgmemServer.start({ database: 'app', prepare: ({ url }) => migrate(url) });
const run = spawnSync('bun', ['test', '--isolate', '--preload', '@pgmem/core/register'], {
  stdio: 'inherit',
  env: { ...process.env, ...pg.env() },
});
await pg.close();
process.exit(run.status ?? 1);
```

`bun test` has no global setup and shares one process by default, so a small script starts pgmem and runs the tests with `--isolate`.

</TabItem>
</Tabs>

`@pgmem/core/register` forks the snapshot and writes the fork's URL to `DATABASE_URL` before the test file's imports run, so application code that builds its client at import time connects to that file's copy. Test files run in parallel, each on its own fork. Set `PGMEM_ENV` to write other variable names instead.

## Share the prepared database with read-only tests

Tests in one file share that file's fork. A file whose tests only read needs nothing else:

```ts
import { expect, test } from 'vitest';
import { prisma } from '../src/db'; // built from process.env.DATABASE_URL

test('counts users', async () => {
  expect(await prisma.user.count()).toBe(0);
});
```

<Aside type="caution">
A write in one test is visible to the rest of the file. Reset between tests as below as soon as any test in the file writes.
</Aside>

## Reset or fork per test for tests that write

`reset()` puts the file's fork back to the snapshot in place. The URL and the client's pooled connections stay valid, and pooled connections keep their prepared statements.

<Tabs syncKey="node-runner">
<TabItem label="Vitest">

```ts title="test/reset.ts"
import { beforeEach } from 'vitest';
import { currentFork } from '@pgmem/core';

beforeEach(() => currentFork().reset());
```

```ts title="vitest.config.ts"
setupFiles: ['@pgmem/core/register', './test/reset.ts'],
```

</TabItem>
<TabItem label="Jest">

```js title="test/reset.js"
const { currentFork } = require('@pgmem/core');

beforeEach(() => currentFork().reset());
```

```js title="jest.config.js"
setupFilesAfterEnv: ['./test/reset.js'],
```

</TabItem>
<TabItem label="node:test">

```js
import { beforeEach } from 'node:test';
import { currentFork } from '@pgmem/core';

beforeEach(() => currentFork().reset());
```

</TabItem>
</Tabs>

```ts title="test/users.test.ts"
import { expect, test } from 'vitest';
import { prisma } from '../src/db';
import { signUp } from '../src/blog';

test('sign up', async () => {
  await signUp('alice@example.com');
  expect(await prisma.user.count()).toBe(1);
});

test('the next test starts from an empty database', async () => {
  expect(await prisma.user.count()).toBe(0);
});
```

**Seed in `beforeAll`, reset to it.** Snapshot the fork after file-level seeding, and reset to that snapshot instead of the run's:

```ts
import { beforeAll, beforeEach } from 'vitest';
import { currentFork, type PgmemSnapshot } from '@pgmem/core';

let seeded: PgmemSnapshot;
beforeAll(async () => {
  await seedOrders(process.env.DATABASE_URL!);
  seeded = await currentFork().snapshot();
});
beforeEach(() => currentFork().reset({ snapshot: seeded }));
```

**Concurrent tests** cannot share one fork. Give each its own with `withFork`, and pass the URL to code that accepts one:

```ts
import { withFork } from '@pgmem/core';
import { test } from 'vitest';

test.concurrent('imports a file', async () => {
  await withFork(async (fork) => {
    const app = createApp({ databaseUrl: fork.url });
    await app.importCsv('fixtures/orders.csv');
  });
});
```

## Things to know

- **A fork is one PostgreSQL session** shared by all its connections, the way a transaction-mode pooler shares one. Pools work, but `SET`, temp tables and advisory locks are shared; use `SET LOCAL`.
- **Query through the transaction handle** inside a transaction callback. A query on another pooled connection would wait for the transaction to end; pgmem ends that wait after `waitTimeoutMs` (default 2 s) with SQLSTATE 55P03 and a message naming both connections.
- **`reset` waits for open transactions** and fails with code `busy` after `timeoutMs` (default 5 s).
- **Forks belong to the process that made them** through `@pgmem/core/register`, `fork()` or `withFork()`, and close when it exits.
