JVM 向けの pgmem は 3 つのアーティファクトでできています。クライアントの `io.github.shibukawa.pgmem:pgmem`、JUnit 5 拡張の `io.github.shibukawa.pgmem:pgmem-junit5`、プラットフォームごとの classifier でバイナリを配る `io.github.shibukawa.pgmem:pgmem-native` です。クライアントはサードパーティの実行時依存を持たないので、JDBC ドライバは自分で追加してください。

## 依存関係

<Tabs syncKey="jvm-build">
<TabItem label="Gradle (Kotlin DSL)">

```kotlin title="build.gradle.kts"
dependencies {
    testImplementation("io.github.shibukawa.pgmem:pgmem-junit5:0.1.0")          // io.github.shibukawa.pgmem:pgmem も入る

```

classifier は `linux-x86_64`、`linux-arm64`、`darwin-arm64`、`windows-x86_64`、`windows-arm64` です。複数のプラットフォームでビルドするなら、5 つ全部に依存するのではなく、Maven のプロファイルや Gradle の OS 判定プラグインでプラットフォームごとに 1 つを選んでください。バイナリは初回に `~/.cache/pgmem/<version>/` へ展開されます。Java 17 以降が必要です。

## 基本の流れ

<Steps>

1. **プロセスを起動します。** `Pgmem` は `AutoCloseable` で、閉じるとすべてのサーバーが止まります。

   <Tabs syncKey="jvm-lang">
   <TabItem label="Java">

   ```java
   try (Pgmem pg = Pgmem.builder().database("app").start()) {
       Server template = pg.template();
       System.out.println(template.jdbcUrl()); // jdbc:postgresql://127.0.0.1:54321/app?user=postgres&sslmode=disable
   }
   ```

   </TabItem>
   <TabItem label="Kotlin">

   ```kotlin
   Pgmem.builder().database("app").start().use { pg ->
       val template = pg.template()
       println(template.jdbcUrl())
   }
   ```

   </TabItem>
   </Tabs>

   ビルダーにはほかに `user(...)`、`param("shared_buffers", "128MB")`、`log(true)`、`binary(path)` があります。

2. **スキーマを登録します。** マイグレーションツールを使います。[マイグレーションツール](#マイグレーションツール)を参照してください。

3. **シードデータを入れます。** [シードデータ](#シードデータ)を参照してください。

4. **JDBC で使います。** `jdbcUrl()` にはユーザーと `sslmode` が含まれ、`dataSource()` は `javax.sql.DataSource` を返します。

   <Tabs syncKey="jvm-lang">
   <TabItem label="Java">

   ```java
   try (Connection conn = DriverManager.getConnection(template.jdbcUrl());
        PreparedStatement ps = conn.prepareStatement("SELECT name FROM users WHERE id = ?")) {
       ps.setLong(1, 1);
       try (ResultSet rs = ps.executeQuery()) {
           rs.next();
           String name = rs.getString(1);
       }
   }
   ```

   </TabItem>
   <TabItem label="Kotlin">

   ```kotlin
   DriverManager.getConnection(template.jdbcUrl()).use { conn ->
       conn.prepareStatement("SELECT name FROM users WHERE id = ?").use { ps ->
           ps.setLong(1, 1)
           ps.executeQuery().use { rs -> rs.next(); println(rs.getString(1)) }
       }
   }
   ```

   </TabItem>
   </Tabs>

   この URL で HikariCP のプールを作ることもできます。接続ごとにバックエンドプロセスが起動します。

</Steps>

## マイグレーションツール

<Tabs syncKey="jvm-migrate">
<TabItem label="生 SQL">

```java
String schema = Files.readString(Path.of("src/test/resources/schema.sql"));
try (Connection conn = DriverManager.getConnection(template.jdbcUrl());
     Statement st = conn.createStatement()) {
    st.execute(schema);
}
```

</TabItem>
<TabItem label="Flyway">

```java
Flyway.configure()
      .dataSource(template.jdbcUrl(), template.user(), null)
      .locations("classpath:db/migration")
      .load()
      .migrate();
```

Flyway 10 以降では、テストのクラスパスに `org.flywaydb:flyway-database-postgresql` も必要です。

</TabItem>
<TabItem label="Liquibase">

```java
try (Connection conn = DriverManager.getConnection(template.jdbcUrl())) {
    Database db = DatabaseFactory.getInstance()
            .findCorrectDatabaseImplementation(new JdbcConnection(conn));
    new CommandScope("update")
            .addArgumentValue("database", db)
            .addArgumentValue("changelogFile", "db/changelog/db.changelog-master.yaml")
            .execute();
}
```

</TabItem>
</Tabs>

## スナップショットとフォークを直接使う

```java
try (Pgmem pg = Pgmem.builder().database("app").start()) {
    migrate(pg.template().jdbcUrl());
    Snapshot snap = pg.template().snapshot();          // 開いているトランザクションを待つ。30 秒
    try (Fork fork = snap.fork()) {                     // 専用の複製
        DataSource ds = fork.dataSource();
        // ...
    }
}
```

`snapshot()` の前に、テンプレートへの接続はすべてコミットするか閉じてください。[次のページ](../testing/)の JUnit 5 拡張は、これをテストのライフサイクルに組み込みます。
