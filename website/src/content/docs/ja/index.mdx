## 同じテストスイート、2 つの実行モデル

小さなショップのデータ層に 70 本のテスト（参照のみ 50 本、更新 20 本）を書きました。共有の PostgreSQL サーバー 1 台では、更新テストは共有データのリセットを挟んで 1 本ずつ順番に走るしかありません。pgmem ではマイグレーションとシードデータの投入後にスナップショットを 1 回取り、参照テストはそのデータベースを共用し、更新テストだけが自分のコピーをフォークするので、スナップショット以降はすべて並列に走ります。

<ModelCaseChart lang="ja" variant="hero" />

スイートの中身、計測ハーネス、各ノードの時間は[ベンチマーク](/pgmem/ja/benchmarks/)のページで説明しています。プロジェクトは [`bench/modelcase`](https://github.com/shibukawa/pgmem/tree/main/bench/modelcase) にあります。

<CardGrid>
	<Card title="本物の PostgreSQL" icon="approve-check">
		PostgreSQL 18.3 を WebAssembly にコンパイルし、Go に変換したものです。SQL の解釈もプランナの挙動もエラーコードも、エミュレータではなく PostgreSQL そのものです。
	</Card>
	<Card title="インストールするものがない" icon="rocket">
		各言語で依存はひとつ。Docker デーモンも、CI 上のコンテナランタイムも要りません。ディスクにも書き込みません。
	</Card>
	<Card title="読み取りは共有、書き込みは分離" icon="random">
		マイグレーションとシードは一度だけ。読み取り専用テストではフォークを共有し、書き込みテストには専用の複製を渡します。書き込みテスト同士も並列に走らせられます。
	</Card>
	<Card title="ドライバを選ばない" icon="puzzle">
		PostgreSQL のワイヤプロトコルで待ち受けるので、pgx、psycopg、JDBC、node-postgres、ORM、マイグレーションツールがそのまま動きます。
	</Card>
</CardGrid>

## 5 行でデータベース

<Tabs syncKey="lang">
<TabItem label="Go">

```go
s, err := pgmem.Start(ctx, pgmem.Options{Database: "app"})
if err != nil {
	t.Fatal(err)
}
defer s.Close()
db, _ := sql.Open("pgx", s.DSN())
```

</TabItem>
<TabItem label="Python">

```python
import pgmem, psycopg

with pgmem.start(database="app") as pg:
    with psycopg.connect(pg.template.dsn) as conn:
        conn.execute("SELECT 1")
```

</TabItem>
<TabItem label="Java">

```java
try (Pgmem pg = Pgmem.builder().database("app").start();
     Connection conn = DriverManager.getConnection(pg.template().jdbcUrl())) {
    conn.createStatement().execute("SELECT 1");
}
```

</TabItem>
<TabItem label="Node.js">

```ts
import { PgmemServer } from '@pgmem/core';
import pg from 'pg';

await using server = await PgmemServer.start({ database: 'app' });
const client = new pg.Client({ connectionString: server.url });
```

</TabItem>
</Tabs>

## よくある選択肢との比較

同じスキーマ、同じクエリ、同じテスト単位の分離を、同じマシンで計測しました。比較相手は公式イメージを使った `docker run`、Testcontainers、devbox で入れた PostgreSQL です。

<BenchmarkOverview lang="ja" />

現在の darwin/arm64 向け strip 済み pgmem バイナリは、エクスポートを絞った
AOT バックエンドを含めて 36.7 MB です。ベンチマークページには pgmem だけを
再計測した最新値を記録し、比較対象は再現可能な基準値として残しています。

クエリ性能、計測方法、再現手順は[ベンチマーク](/pgmem/ja/benchmarks/)のページにあります。
