## One test suite, two execution models

A small shop's data layer with 70 tests: 50 that only read, 20 that
write. On a shared PostgreSQL server, here one started with
Testcontainers, the writing tests have to wait for each other, each
behind a reset of the shared data. With pgmem the suite
takes one snapshot after the migrations and seed data; the read-only tests
share that database and every writing test forks its own copy, so
everything after the snapshot runs in parallel.

<ModelCaseChart lang="en" variant="hero" />

The suite, the harness and every node's timing are described on the
[benchmarks page](/pgmem/benchmarks/); the project is in
[`bench/modelcase`](https://github.com/shibukawa/pgmem/tree/main/bench/modelcase).

<CardGrid>
	<Card title="The real thing" icon="approve-check">

	</Card>
	<Card title="Nothing to install" icon="rocket">
		One dependency per language. No Docker daemon, no container runtime on CI, no files written to disk.
	</Card>

	</Card>

## Five lines to a database

<Tabs syncKey="lang">
<TabItem label="Go">

```go
s, err := pgmem.Start(ctx, pgmem.Options{Database: "app"})
if err != nil {
	t.Fatal(err)
}
defer s.Close()
db, _ := sql.Open("pgx", s.DSN())
```

</TabItem>
<TabItem label="Python">

```python
import pgmem, psycopg

with pgmem.start(database="app") as pg:
    with psycopg.connect(pg.template.dsn) as conn:
        conn.execute("SELECT 1")
```

</TabItem>
<TabItem label="Java">

```java
try (Pgmem pg = Pgmem.builder().database("app").start();
     Connection conn = DriverManager.getConnection(pg.template().jdbcUrl())) {
    conn.createStatement().execute("SELECT 1");
}
```

</TabItem>
<TabItem label="Node.js">

```ts
import { PgmemServer } from '@pgmem/core';
import pg from 'pg';

await using server = await PgmemServer.start({ database: 'app' });
const client = new pg.Client({ connectionString: server.url });
```

</TabItem>
</Tabs>

## Compared with the usual options

The same schema, queries and per-test isolation, measured on one machine against the official image with `docker run`, Testcontainers, and a devbox-installed PostgreSQL.

<BenchmarkOverview lang="en" />

The current stripped darwin/arm64 pgmem binary is 36.7 MB, including the
export-pruned AOT backend. The benchmark page records the latest pgmem-only
rerun and keeps the comparison baselines reproducible.

Query latency, methodology and how to reproduce are on the [benchmarks page](/pgmem/benchmarks/).
